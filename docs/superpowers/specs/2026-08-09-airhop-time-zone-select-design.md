# AirHop: выбор часового пояса

## Цель

Заменить свободный ввод часового пояса в настройках AirHop на нативный
выпадающий список. Пользователь должен выбирать валидное IANA-значение, а новый
профиль — получать часовой пояс браузера без изменения уже сохранённых центров.

## Интерфейс

- Поле «Часовой пояс» использует существующий `BookingSelect` со стрелкой.
- Список содержит все IANA-зоны, доступные через
  `Intl.supportedValuesOf("timeZone")`, в алфавитном порядке.
- Текущее значение всегда присутствует в списке, даже если среда не вернула его
  в `supportedValuesOf`.
- Первым пунктом показывается действие
  «Определить автоматически — <IANA-зона браузера>».
- После выбора автоматического пункта поле принимает конкретную IANA-зону;
  служебное значение действия никогда не сохраняется.
- Подсказка объясняет выбор из списка и автоматическое определение вместо
  предложения вводить IANA-строку вручную.

## Автоопределение

Часовой пояс определяется через
`Intl.DateTimeFormat().resolvedOptions().timeZone` и проверяется существующей
IANA-валидацией. Если API отсутствует, возвращает пустое или некорректное
значение, используется `Europe/Moscow`.

Для нового локального профиля начальное значение берётся из автоопределения.
Если профиль уже сохранён, его `organization.timeZone` остаётся неизменным.
Таким образом обновление интерфейса не меняет расписание и даты существующих
центров без явного действия пользователя.

## Данные и границы

- В доменной модели продолжает храниться строка IANA; схема данных и миграция не
  меняются.
- Список и автоопределение оформляются чистыми функциями в booking-модуле, чтобы
  не связывать браузерные API с компонентом формы и проверять их отдельно.
- Для старой среды без `Intl.supportedValuesOf` используется небольшой резервный
  список, обязательно содержащий `Europe/Moscow`, `UTC`, определённую и текущую
  зоны.
- В этой итерации не добавляются поиск по городам, локализованные названия зон и
  постоянный режим «следовать за часовым поясом устройства».

## Проверки

- Unit-тест подтверждает валидное автоопределение и резерв
  `Europe/Moscow` при некорректном результате.
- Unit-тест подтверждает алфавитный IANA-список, отсутствие дублей и включение
  текущего значения.
- E2E-тест подтверждает, что поле является `select`, содержит автоматическое
  действие, позволяет выбрать другую зону и сохраняет её после перезагрузки.
- После реализации выполняются целевые unit/E2E-тесты, typecheck и сборка E2E.
