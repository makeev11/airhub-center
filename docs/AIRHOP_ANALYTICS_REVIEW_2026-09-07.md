# Ревью first-party аналитики AirHop — 7 сентября 2026

Проверен путь от автоматической вставки сборщика при публикации сайта до
хранения в Center, экранов аналитики и чтения агентом-Аналитиком. Найденные
ниже ошибки исправлены. Это ревью реализации и локальные проверки; оно не
является подтверждением развёртывания на действующем сайте.

## Найдено и исправлено

| Проблема | Последствие | Исправление |
| --- | --- | --- |
| Отправка без подтверждения и повторов | Потеря событий при временной сетевой ошибке | Общая ограниченная очередь сайта/формы, повтор исходных eventId, дедупликация PostgreSQL |
| Доступ к storage вне try/catch | SecurityError мог прервать создание формы | Защищены сами getter хранилища; стабильная идентичность и очередь в памяти |
| Конверсия смешивала разные попытки и периоды | Неверный процент, скрытый ограничением 100% | Воронка и процент включают только попытки с наблюдаемым открытием в периоде |
| Необязательные analytics-поля могли отклонить заявку | Повреждённая телеметрия мешала основной цели сайта | Некорректная optional attribution отбрасывается, Booking остаётся валидной |
| Постоянный URL скрипта с годовым immutable cache | Исправления не доходили до посетителей | Content hash в URL, обновление managed script tag и корректная revalidation |
| Обработчик редиректа принимал обратную косую черту | Возможен выход с разрешённого origin | Backslash запрещён в destination path |
| Вставка пакета отдельными запросами и повторные проверки | Лишние обращения к БД | Один INSERT на пакет, одна проверка каждого уникального branch/link |
| Части отчёта читались в разные моменты | Карточки могли расходиться во время поступления событий | Один SQL statement/MVCC snapshot, materialized CTE, timeout 5 секунд |
| Несколько источников у одной сессии | Сумма источников превышала число сессий | Одно первое наблюдаемое происхождение сессии в выбранном периоде |
| Фиксированные 30 дней у Аналитика | Нельзя ответить за неделю или другой период | days=1..366 в MCP, read-only CLI и выбор 7/30/90/366 дней в интерфейсе |
| Отсутствовали детали и свежесть | Нельзя понять страницы, тип контакта и поступление событий | Просмотры, страницы, контакты, воронка сессий, generatedAt/timeZone/firstEventAt/lastEventAt |
| Ошибка записи открытия могла ломать специальную ссылку | Человек не попадал на страницу | Savepoint для необязательного события и отдельная квота ссылок |
| Незавершённый запрос переживал смену организации | Старая очередь могла восстановиться после очистки | Dispose отменяет запрос и запрещает последующую запись outbox; добавлен регрессионный тест |

## Доставка и пределы

- Нет сторонних библиотек, tag manager, обхода DOM по таймеру или чтения полей форм.
- Сборщик загружается с defer. Обычные действия сайта не ожидают сетевого ответа.
- Полный исходник с доставкой: около 12,8 КБ, gzip около 4,2 КБ.
  Автоматические бюджеты: 16 KiB raw и 5 KiB gzip. Рост относительно прежних
  7,1 КБ raw обусловлен повторной доставкой и защитой от повреждённых ответов.
- Очередь: до 40 событий, до 23 часов, до 6 событий за запрос, до 6 неудачных
  фоновых попыток с backoff; Retry-After соблюдается. Сеть online/новая страница
  возобновляет попытки. Пакеты не превышают лимит HTTP body 16 KiB.
- Beacon не является подтверждением: неподтверждённые eventId остаются для
  повторной доставки. Ответ 200 с HTML тоже не считается успешной записью.
- Сырой IP, значения контактов, форма, полный referrer, query/fragment не
  попадают в таблицу аналитики. Путь управления Booking нормализован без токена.
- Browser Origin другого сайта отклоняется. Текущий контракт — same-origin.

## Метрики и источник истины

`airhop_site_analytics_events` — append-only история на 13 месяцев с tenant
fencing. Дедупликация — по `(community_id, event_id)`. Ссылки и события связаны
с организацией составными внешними ключами. `booking_created` создаётся только
сервером в транзакции Booking Core; клиент не может прислать этот факт.

Сессия — случайный идентификатор с idle-окном 30 минут, посетитель — браузер,
journey — попытка записи. Длинная форма обновляет sessionId при возобновлении,
сохраняя journeyId. Общее число Booking и конверсия наблюдаемых попыток имеют
разные, явно определённые основания. Дневные границы — timezone организации;
сегодня неполный день. Разрезы страниц/источников ограничены 100 строками с
признаками усечения; итоговые KPI считаются по всему периоду.

Экран и `airhop_read(resource="site_analytics", days=7)` получают один отчёт.
CLI: `buzz airhop site-analytics --days 7`, `buzz airhop tracking-links`.
Аналитик остаётся read-only; prompt требует проверять свежесть и ограничения
данных перед выводами. Методика проверки знаменателей взята из Validate Data.

## Проверки

- Отдельная локальная БД `airhop_analytics_review_20260907`: применены настоящие
  миграции; проверены пустой отчёт, timezone, идемпотентная доставка, rollback
  плохого пакета, изоляция организаций и когорта воронки.
- Реальное создание Booking: повтор команды не добавляет конверсию; отказ по
  вместимости не считается успехом; Booking без наблюдаемого открытия не
  увеличивает числитель конверсии открытых попыток.
- Полный отчёт по 50 005 событиям: **339 мс** на локальном Postgres, один замер.
  Это проверка порядка величины, а не обещание latency на production/VPS.
- Проверены retry, Retry-After, byte/count/age limits, сохранение очереди между
  страницами, beacon без ack, fallback HTML, отказ storage и изоляция плохого
  события в пакете. Проверены подпись и выбор периода для Аналитика.
- Worker: 24 теста. TypeScript и desktop lint проходят.
- Полный `just ci` прошёл: форматирование, статические проверки, unit-тесты,
  desktop/web-сборки и native/mobile-тесты. Последняя защита lifecycle очереди
  дополнительно проверена профильными клиентскими и worker-тестами.
- Визуальный QA реального компонента: 1280 px, 390 px и пустой отчёт;
  воспроизводимый стенд — `desktop/scripts/review-site-analytics.mjs`.

## Практические ограничения и запуск

Браузерную телеметрию нельзя гарантировать на 100%: блокировщик, закрытие
браузера/вкладки, очистка хранилища или offline дольше срока очереди могут
привести к пропуску. Серверные Booking сохраняются независимо от доставки
предшествующих браузерных событий. Отсутствие данных не равно нулю посетителей.
Подписанная cookie специальной ссылки действует до 30 дней; отложенная отправка
использует cookie, действующую в момент запроса. Это не multi-touch attribution.

Перед production нужны согласованные версии Center и HQ worker, повторная
публикация сайта и same-origin reverse proxy с Host, зарегистрированным для
его tenant. `X-Real-IP` должен быть доверенным заголовком, перезаписываемым proxy;
иначе квота будет общей для посетителей за адресом proxy. Внешние origin и
другие домены без tenant mapping текущим профилем не поддерживаются.

Live rollout и сравнение LCP/INP на действующем сайте в это локальное ревью не
входили. Общий `just test` не завершён успешно: Docker socket недоступен,
подъём Postgres/Redis завершился таймаутом. Профильные SQL проверки выполнены
напрямую в отдельной локальной БД.
