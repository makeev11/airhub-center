## Реализованный объём

| Роль | Исполнение | Настройки |
|---|---|---|
| Физ | Hermes, общий граф, проверяемая передача задач | Включение роли, накопление и применение опыта |
| Внутренний администратор | Hermes, общий граф, разрешённые операции с согласованием | Дни рождения сегодня и заранее, возраст, время, филиалы или выбранный канал |
| Аналитик | Hermes, общий граф, чтение фактов | Ежедневный/еженедельный отчёт, время, канал, пять разделов |
| Контент-маркетолог | Hermes, общий граф, существующее согласование HQ | Разрешение изменения контента сайта |
| Родительский администратор | Существующий размещённый Hermes, общий граф с отдельными лимитами и темпом ответа | Включение роли, режим накопления/применения опыта; настройки размещения отдельно |

Четыре внутренние встроенные персоны по умолчанию используют `Airhop Hermes`.
У существующих персон обновляется только отсутствующий выбор runtime; явно выбранный
runtime персоны сохраняется. Для встроенной команды запуск общего Hermes, Claude
или Codex блокируется: их штатные инструменты обходят продуктовый граф. Старый продуктовый
путь Buzz Agent остаётся совместимым. При согласовании экземпляров источником настроек остаётся
персона. Новому профилю нужна установка: отсутствующий runtime не заменяется молча другим.

Installer закрепляет NousResearch Hermes на коммите
`e624e9fde561e1add9388384012b295fde669ade`, проверяет SHA-256 архива и ставит фиксированные
зависимости с Airhop ACP patch. Профили разделены по relay и ключу агента. Личные память,
профиль и произвольные инструменты Hermes не подключаются; доступны продуктовые MCP-tools.
Ключи провайдера не записываются в файлы профиля. Инструкция:
[Hermes runtime](../integrations/hermes-airhop-team-runtime/README.md).

Общий граф исполняется вокруг инструментов всех пяти ролей:
**контекст → выбор → точечное чтение / разрешённое действие → один ответ → завершение**.
Есть лимиты чтений, попыток, повторов кэша и изменений. После изменения старый контекст
сбрасывается. Для обязательного обновления перед передачей родительского диалога оставлен
ограниченный резерв, чтобы исчерпание обычного бюджета не блокировало завершение.

Это граф исполнения и существующие связи Core: семья → ребёнок → запись/группа → филиал.
**Отдельная графовая БД, универсальный GraphRAG и универсальный язык обхода не добавлены.**
Поиск знаний остаётся SQL/FTS; агенты выбирают подходящие типизированные инструменты.

## Доступ команды

Встроенные агенты получают режим обращений сотрудников. Старые ограничения «только
владелец» обновляются при согласовании команды владельцем. Сервер проверяет допуск
в организацию и рабочий канал, отзыв доступа, деактивацию и сервисные личности.
Новый сотрудник не обязан сначала опубликовать профиль. Настройки видны сотрудникам;
менять их и одобрять процедуры могут владелец и администратор организации.

Внутренняя маршрутизация пока относится к зарегистрированному рабочему каналу команды,
а не к произвольным каналам. Режим `anyone` не отменяет серверные границы доступа.

## Обязанности и повторы

По умолчанию администратор напоминает о днях рождения сегодня и за два дня, в 09:00
по часовому поясу организации. Данные берутся из актуальных связей ребёнка с филиалами;
на каждый канал формируется один список. Возраст вычисляется на дату рождения;
29 февраля в невисокосный год считается 28 февраля. Неизвестный филиал не выдумывается.
Ребёнок с действующими связями с несколькими филиалами может попасть в каждый из них.

Аналитика использует канонические показатели центра за завершённый день или семь дней,
выбранные разделы, точность валют и явное отображение пропусков. Новый worker заменяет
старую регулярную публикацию меняющегося месячного снимка. Эти фактические уведомления
вычисляются без вызова модели.

Задания сохраняются с неизменными входными данными: повторная отправка получает тот же
идентификатор события. Есть блокировки параллельных workers и проверка политики/канала
перед публикацией. Неподходящий канал одного филиала не блокирует остальные филиалы.
Изменение настройки отменяет старые ожидающие сообщения. Если расчёт
за этот день уже состоялся, настройки применятся к следующему расписанию — повторную
рассылку в этот день они не запускают.

Квитанция в БД допускает только один внутренний ответ на конкретное входящее событие,
включая гонку процессов и потерянное подтверждение HTTP. Части ответа объединяются
в одно сообщение, одинаковые части удаляются. Это не семантическая дедупликация похожих
сообщений с разными исходными событиями.

Политики хранятся на сервере, изменяются подписанными командами с версией и квитанцией
повтора. При конфликте версий UI сохраняет черновик. Главный переключатель внутренней
роли управляет обязанностями и локальным запуском чата; незапущенный чат показан отдельно.
Разрешение контента сайта проверяется при подготовке и подтверждении, вместе с существующим
согласованием HQ; оно не разрешает произвольное изменение кода или публикацию без согласования.

## Накопление опыта

Первая версия сохраняет порядок категорий успешно прочитанных источников после
опубликованного ответа. Ошибка выполнения запроса к серверу исключает кандидата. Клиентские тексты, идентификаторы, факты и исполняемый код
не сохраняются в процедуру. Для рассмотрения нужны три различных ответа.
**Число наблюдений не является оценкой качества.**

По умолчанию опыт только собирается. Владелец/администратор вручную выбирает допустимую
процедуру и может её откатить; история решений сохраняется. Активная процедура — подсказка
порядка чтения для подходящей задачи; она не расширяет права и не отменяет граф.
Самостоятельное переписывание навыков Hermes, автоматическая проверка качества,
A/B-эксперименты и автоматическое продвижение версий не реализованы.

   Рост конверсии и процент экономии пока не измерены.

Серверные уведомления не зависят от открытого desktop. **Внутренние чаты пока работают

в Rust-каталоге; интерфейс не вводит второй каталог возможностей.
