# «Хюге»: приёмка аналитики на demo.airhop.ru

## Границы релиза

Пользователь разрешил обновить существующий `demo.airhop.ru`, сохранив данные,
передать архив исходников без `.env` и секретов на его сервер `46.173.25.23`,
а также обновить локальное приложение AirHop Center с сохранением аккаунта.
Production, права пользователей, подключение мессенджеров и платежи не входят
в этот rollout.

- Compose project: `buzz-demo`; меняется только сервис `relay`.
- Community: `c88a2770-b2ca-4566-bcb3-fa3d8919a537`.
- Organization: `7e510ed1-15a1-4a75-8d3d-33f924fe18a0`.
- Сайт пилота: `https://demo.airhop.ru/airhop/hygge/`.
- HQ organization: `2554d9a1-ada4-4794-88a7-103ebf1422d9`.
- Прежний образ демо: `airhub-center-relay:f9730f5-booking-cta-20260907`.
- Установленный образ: `airhub-center-relay:analytics-20260907-879f9cda-hygge`.
- Digest: `sha256:4a7c892f03ff8faedc4f11a047f23e9ae6613de0a640bc341d2a96e974af618b`.

  `879f9cda81fd5d78e59dc0b0b55b11c799fd6a3206b183c8b24136764fdf8b44`.

  `bdcfdb3af6e3b059078244bf2124c957c0037e46e9fc2cd025a1126204485b08`.
- Public JS: `index-B_W4CPwJ.js`. Последняя sticky CTA и старые hashed assets
  из предыдущего demo-образа сохранены.

Это noindex-экспорт существующего примера из соседнего `airhop-site`, не
публикация всего маркетингового сайта. Разметка и оформление сохранены;
расписание и цена пробного читаются из публичного API Center. Неверная
организация закрывает переход к записи. Сайт и `/booking` находятся на одном
origin и используют общий идентификатор браузера/сессии и источник перехода.
Фиксированные UTM старой междоменной ссылки в этом экспорте удалены, чтобы не
перезаписывать входящую кампанию.

Форма `/booking` загружается только по клику в same-origin iframe внутри
native dialog: адрес страницы не меняется, отдельной копии BookingFlow нет.
Escape/кнопка закрытия возвращают фокус; без JavaScript остаётся обычная ссылка.

## Воспроизводимые проверки

`desktop/scripts/build-hygge-pilot.mjs` экспортирует только две страницы
«Хюге», забирает локальные ресурсы и вставляет точный shared collector из HQ.
`check-hygge-pilot.mjs` проверяет его локально с подставным каталогом: события,
сохранение источника между страницами, неверный tenant, ошибки ресурсов и
горизонтальный overflow при 1280/390 px. Это fixture QA, не live-доказательство.

`check-hygge-live.mjs` работает только с фиксированным демо, требует флаги
`--allow-demo-events --allow-demo-booking` и новый каталог вывода
`/private/tmp/airhop-hygge-release.*`. Он создаёт **одну настоящую тестовую
заявку** с вымышленными именами и телефоном `+12025550124`, каналом связи `none`.
Заявка остаётся на подтверждении: тест не звонит, не отправляет сообщения и
не отмечает оплату. Повтор исходной команды проверяет идемпотентность.

Перед запуском создаётся `live-attempt.json` с уникальной кампанией. Повторный
запуск в том же каталоге запрещён даже при предыдущем падении. Сначала нужно
проверить сохранённую кампанию, чтобы не создавать лишние заявки. Management
token, подписи авторизации и значения реальных контактов не входят в отчёт.

`read-hygge-analytics.mjs` выполняет только read-only SQL через SSH:
сверяет сохранённую кампанию, уникальные события, tenant, пять этапов,
единственную серверную конверсию и собирает тот же SQL-отчёт, который читает
staff API. Такая проверка не заменяет отдельный тест авторизации, интерфейса
сотрудника и вызова `airhop_read` самим Аналитиком.

## Переключение и возврат

`deploy/airhop/deploy-analytics-demo-20260907.sh` — одноразовый rollout с
фиксированными target, предыдущим образом и версией схемы 52. Он проверяет
контрольную сумму source label нового образа, делает custom-format `pg_dump`,
восстанавливает его в отдельную БД `buzz_analytics_preflight_20260907` и
применяет там миграцию 0053 до обновления живого relay.

Резервная копия остаётся на сервере в
`/opt/airhop/backups/demo-before-analytics-20260907` с закрытыми правами.
Приложение перед заменой сохранено локально в
`/private/tmp/airhop-hygge-release.vKgyLg/previous-app-bundle`.

При ошибке postflight скрипт возвращает прежний образ с
`BUZZ_AUTO_MIGRATE=false`: старый SQLx-бинарник не знает миграцию 53.
Аддитивные таблицы аналитики и существующие данные остаются на месте.
Автоматическое восстановление поверх живой БД или удаление таблиц не допускается.
Production relay, база, Redis, MinIO, pairing и агентские контейнеры проверяются
по прежним ID/времени старта и не должны пересоздаваться.
