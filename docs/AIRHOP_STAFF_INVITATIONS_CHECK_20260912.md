# Проверка добавления сотрудников — 12 сентября 2026

Исправления внесены в рабочую копию. На сервер и в установленное приложение они пока не выложены.

## Найденные проблемы

- API выдаёт ссылку `/invite/<code>`, а Docker-образ Airhop обслуживает сборку `desktop` с `VITE_AIRHOP_PUBLIC_WEB=1`. В этой сборке не было страницы приглашения. Прогон нового браузерного теста на исходной публичной сборке воспроизвёл отсутствие страницы входа.
- Открытый список сотрудников не обновлялся после принятия приглашения на другом устройстве. Теперь он запрашивает актуальный состав каждые 15 секунд, пока открыт.
- При частичной ошибке пакетного добавления успешно добавленные люди оставались среди получателей для повторной отправки. Теперь остаются только необработанные получатели, а форма блокируется на время всей операции.
- Ошибка выдачи приглашения отображалась как ошибка копирования. Теперь форма различает создание и копирование и сохраняет сообщение об ошибке рядом с действием.
- При ручной вставке ссылки в первоначальный экран терялось подтверждение условий входа. Теперь `policy_receipt` доходит до подписанного запроса принятия приглашения.

## Результат

Публичная страница открывает `airhop://join` — схему, зарегистрированную приложением Airhop Center. Она показывает условия, получает подтверждение только после согласия, позволяет повторить неуспешную загрузку и предоставляет ссылку для ручного входа. Запросы условий ограничены тайм-аутом. Есть русский и английский интерфейс.

Новый сотрудник входит с ролью `member`; создание команды владельца при этом не запускается. Серверные правила доступа и таблицы приглашений не изменены.

## Проверки

- 44 модульных теста: API приглашений, разбор ссылок, локализация ошибок, первоначальный вход, передача подтверждения условий.
- 7 браузерных проверок приложения с mock relay/Tauri: принятие вставленной ссылки, добавление сотрудника, распознавание дубля, частичная ошибка и повтор, обновление открытого списка, ошибка создания и повтор, копирование и лимит использований.
- 4 браузерные проверки производственной публичной сборки без Tauri bridge: страница приглашения и повторная загрузка, условия и передача подтверждения, русский интерфейс при ширине 390 px, отказ сервиса условий и повтор.
- TypeScript, Biome для изменённых файлов, ограничения размеров файлов и размеров текста прошли.

Команды повторного запуска из активированного Hermit:

```sh
cd desktop
pnpm test:e2e:public
pnpm build:e2e
AIRHOP_E2E_PORT=4297 pnpm exec playwright test --project=smoke airhop-staff-invites invite-link-copy
```

Публичные тесты проверяют настоящий статический bundle, но ответы API условий подменены. Проверки рабочего приложения подменяют relay и Tauri. Запись в настоящий Postgres, системное открытие установленного приложения и вход второго физического устройства в развёрнутый центр не проверены: локальный Docker daemon недоступен, выкладка не выполнялась.
